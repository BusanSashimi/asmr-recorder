# Display previews before screen selection

Research date: 2026-10-19. Scope: options and recommendation for Recording Mode → Add Source → Screen. The implementation and validation results are recorded below separately from the original research.

## Recommendation

For the current custom display chooser, use **small `SCScreenshotManager` snapshots**, taken when the chooser opens, with a Refresh action as the baseline. If automatic freshness is needed, refresh at a bounded interval only while visible. Start with a 320–480 px longest edge, one in-flight batch, and a proposed 2–3 second interval; profile these values before shipping. This gives recognizable previews inside the existing flow without maintaining a separate video stream per display. Keep the selected image for the crop step, optionally fetching one larger still.

Choose **`SCContentSharingPicker` instead** if the priority becomes Apple’s standard selection/permission experience or future window/application selection. Apple recommends its system picker, and user selection authorizes the selected content for the capture session without a separate full-screen permission grant. That is a meaningful advantage, but adopting it here requires carrying its native filter into capture rather than only changing the chooser UI. [Apple framework guidance](https://developer.apple.com/documentation/screencapturekit), [Apple privacy session, 6:18–6:46](https://developer.apple.com/videos/play/wwdc2023/10053/?time=378)

## Options

| Option | Experience and fit | Main tradeoff |
| --- | --- | --- |
| Screenshot thumbnails, with bounded refresh | Custom cards show all available displays; best fit for this request | Requires the app’s existing Screen Recording permission path; periodic stills do not show smooth motion |
| Native `SCContentSharingPicker` | OS selection UI; supports display, window, and app modes; stronger session-scoped consent experience | System-owned presentation rather than app-owned thumbnail cards; native filter and stream lifecycle integration required |
| Thumbnail-sized `SCStream` per display | Smooth live previews inside custom cards | Long-lived capture sessions, surface pools, callbacks, encoding and IPC per display; cleanup becomes more involved |
| Browser `getDisplayMedia()` | Useful for the ordinary browser version | Browser owns selection; cannot populate a custom gallery with previews of every display before consent |

These are capability/architecture comparisons, not benchmark results. Apple explicitly demonstrates live picker thumbnails using separate streams at 284×182, 5 fps, default queue depth, and no audio or cursor. Thus live previews are supported; they are simply more machinery than occasional stills for identifying a few monitors. [Apple live-thumbnail example](https://developer.apple.com/videos/play/wwdc2022/10155/)

## Verified APIs and limitations

- **macOS 14.0:** `SCScreenshotManager.captureImage(contentFilter:configuration:)` and `captureSampleBuffer(contentFilter:configuration:)` support one-frame capture with the existing `SCContentFilter` and `SCStreamConfiguration`; no `SCStream` creation is necessary. Request thumbnail output dimensions directly and preserve aspect ratio. **Do not confuse these with** `captureImage(in:)` (macOS 15.2) or `SCScreenshotConfiguration` / advanced screenshot output (macOS 26.0). Availability was checked in Apple’s DocC metadata and installed SDK headers. [Screenshot manager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager), [original capture method](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(contentfilter:configuration:completionhandler:)), [rectangle method](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(in:completionhandler:)), [advanced configuration](https://developer.apple.com/documentation/screencapturekit/scscreenshotconfiguration)
- **macOS 14.0:** the native picker provides an `SCContentFilter` through observer callbacks for new/existing streams, plus cancellation/failure callbacks. Restrict its modes to a single display for this flow. Use the returned filter directly for screenshots or streaming; rebuilding a filter from a display index should not be assumed to preserve picker authorization. [Picker API](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpicker), [Apple picker/filter integration](https://developer.apple.com/videos/play/wwdc2023/10136/)
- **Permissions differ:** app-enumerated screenshots of all displays follow the broad Screen Recording authorization path. Native picker authorization is scoped to selected content and the capture session, not permanent access to all displays. Denial should produce an explicit unavailable state and stop periodic retries. Exact prompts and grant/relaunch behavior require supported-OS testing; Apple’s custom capture sample documents a permission prompt and restart. [Apple capture sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos), [Apple picker consent explanation](https://developer.apple.com/videos/play/wwdc2023/10053/?time=378)
- **Existing dependency is sufficient for an initial integration:** `Cargo.lock` pins `screencapturekit` **1.5.0**; `Cargo.toml` already enables `async` and `macos_14_0`, and the app minimum is 14.0. That exact release exposes synchronous/async screenshot methods, RGBA extraction, and native picker APIs. The synchronous screenshot method waits for completion, so use a worker or its async counterpart. No major dependency upgrade is intrinsically required. [Pinned screenshot source](https://docs.rs/crate/screencapturekit/1.5.0/source/src/screenshot_manager.rs), [pinned async source](https://docs.rs/crate/screencapturekit/1.5.0/source/src/async_api.rs), [project dependency](../src-tauri/Cargo.toml), [deployment minimum](../src-tauri/tauri.conf.json)
- **Audit the pinned picker wrapper before choosing it:** its Swift observers deliver a single outcome and ignore later updates. Its metadata-rich `show()` path reads included displays/windows/apps through KVC below macOS 15.2; Apple only exposes public `includedDisplays` from 15.2. Prefer avoiding dependence on extracted display metadata on 14.x and retain the filter; a proper ongoing observer bridge would be needed for system-driven reselection. [Exact 1.5.0 Swift bridge](https://docs.rs/crate/screencapturekit/1.5.0/source/swift-bridge/Sources/ScreenCaptureKitBridge/ContentSharingPicker.swift), [Apple included displays availability](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/includeddisplays)
- **Webview support is not simply “WKWebView never has getDisplayMedia.”** Tauri uses the system WKWebView; official WebKit history shows display-capture behavior depends on delegates/version. Keep this app’s native Tauri path. Even where browser capture works, the standard requires a user choice on each call and does not provide an app API to enumerate all screen thumbnails before selection. [Tauri webview reference](https://v2.tauri.app/reference/webview-versions/), [WebKit delegate fix](https://results.webkit.org/commit?id=279566%40main&repository_id=webkit), [W3C Screen Capture working draft §5.1](https://www.w3.org/TR/screen-capture/#dom-mediadevices-getdisplaymedia)

## Proposed interaction and design alignment

Keep the existing focused selection sheet and replace its text-only rows with a responsive two-column gallery, approximately 600 px wide and bounded by the window. Each selectable card contains an aspect-preserving screen image, display label, dimensions, and primary-display badge. Portrait and ultrawide images must remain fully visible rather than being cropped to fit. Show the same chooser for a single display so a preview is always available.

Clicking a card selects it; **Continue** advances to the existing region step with that screen image behind the crop handles. **Cancel** leaves the current section untouched. Refresh updates previews without moving keyboard focus or changing selection. Provide per-card loading/unavailable states and a clear permission recovery action when all previews are unavailable.

Reuse the established `.mat-sheet`, semantic surface/text tokens, SF system typography, blue accent selection/focus, existing radii, and 32 px dialog-footer buttons. Keep the crop overlay's established recording-color treatment. Support keyboard selection, Enter/Continue, Escape/Cancel, VoiceOver labels and selection state, focus return, reduced motion/transparency, light/dark appearance, and the 800×600 minimum window. These are app-specific choices based on the existing [design system](design-system.md), consistent with Apple's guidance for scoped tasks in [sheets](https://developer.apple.com/design/human-interface-guidelines/sheets).

## Implementation seams

1. Add a native snapshot service/command separate from recording-section streams. Resolve a `displayId` against fresh shareable content and return image bytes plus display identity, dimensions, and capture time. Encode in memory; keep thumbnail state ephemeral. Existing `start_screen_stream` replaces a stream with the same section index, so reusing that API for chooser thumbnails could interrupt a section. [Display enumeration](../src-tauri/src/screen.rs), [section stream lifecycle](../src-tauri/src/screen_stream.rs)
2. Add a frontend thumbnail request layer beside `native-screen.ts`: bounded requests, stale-session rejection, per-display loading/error states, and object-URL/bitmap cleanup. Stop refresh on chooser close, hidden app, or mode exit. Keep the last successful preview on a transient failure. Revalidate stable display IDs at confirmation; the current transient array index can address a different monitor after hot-plug/reordering. [Current native bridge](../frontend/src/lib/native-screen.ts), [current chooser](../frontend/src/components/asmr-recorder/preview.tsx)
3. Carry the selected still into `RegionSelector`; the native path currently passes no `MediaStream`, so its crop step has no actual display preview. Reset crop state for each selection/open and verify the mapping between thumbnail pixels, logical display points, backing pixels, and native `sourceRect`, especially Retina/external displays. The current crop initializes state from dimensions once. [Crop component](../frontend/src/components/asmr-recorder/region-selector.tsx), [native crop configuration](../src-tauri/src/screen_macos.rs), [Apple scale-factor explanation](https://developer.apple.com/videos/play/wwdc2022/10155/)

## Validation before shipping

- Test first grant, denial, revoked access, and successful capture on macOS 14.x and the current supported macOS; check the packaged signed app as well as development builds.
- Check one/two/three displays, Retina plus non-Retina, portrait orientation, mirroring, changing resolution, and disconnect/reconnect between preview and confirmation.
- Repeatedly open/close/cancel, select a display, switch modes, and add a source while another section is active; verify stale requests cannot repopulate a closed chooser and active recordings remain intact.
- Measure first-thumbnail latency, CPU, WindowServer memory, app memory, JPEG size and responsiveness while idle versus refreshing; compare periodic snapshots with 5 fps thumbnail streams before claiming a performance winner.
- Confirm thumbnails match their labels and selected crop output. Unit-test identity/stale-result handling and coordinate conversion if implemented; use integration/manual checks for actual permission and capture behavior.

## Implemented and verified — 2026-10-19

The approved baseline is implemented: stills on open and manual Refresh, with no recurring timer. A two-column gallery uses the existing sheet, semantic tokens, radio selection, and fixed footer. Native screenshots are serialized, encoded as JPEG in memory, and bounded to a 480 px longest edge; the crop step requests 1600 px while retaining the thumbnail as a fallback. Closing, switching modes, and superseding requests discard late images and release object URLs.

Display IDs and expected logical dimensions/backing scale are revalidated at crop entry and native startup. Reordering never substitutes another display, and changed/disconnected selections return to the gallery. Crop coordinates remain logical points on macOS. A replacement native stream is prepared before the current stream is released; cancellation and failed preparation preserve the current source. Only complete ScreenCaptureKit frames update the live canvas, preserving its last valid image during idle notifications. [Apple frame-status contract](https://developer.apple.com/documentation/screencapturekit/scframestatus)

The repeated permission failure was traced to ad-hoc signatures: macOS logged a mismatch between the previous hash-based TCC requirement and each rebuilt executable. A free Personal Team Apple Development certificate was created in Keychain with user authorization. The debug-bundle launcher now selects a valid development certificate (or an explicit signing identity), and refuses ad-hoc debug bundles. No account identifiers, certificate names, or private keys are stored in source control. [Apple signing explanation](https://developer.apple.com/forums/thread/819406), [Tauri macOS signing](https://v2.tauri.app/distribute/sign/macos/)

Validation completed on this Mac running macOS 27.0:

- Frontend: **76 tests across 11 files**, production TypeScript/Vite build, and ESLint for the touched components and bridges passed. New controller tests cover ordering, ID preservation, disconnect/geometry changes, stale and cancelled requests, image cleanup, permission denial, visibility, and fallback behavior.
- Rust: **25 library tests** passed, including preview sizing and stream replacement/cancellation. The certificate-signed debug application bundled successfully.
- Real native previews loaded on four displays: Retina primary (4112 × 2658 backing pixels), portrait 1080 × 1920, landscape 2560 × 1440, and portrait 1200 × 1920. Portrait crop output matched the selected centered 540 × 960 region. Cancelling replacement preserved its visible source, and Recording/Editing transitions resumed the source.
- Browser fixtures verified portrait/ultrawide aspect preservation, a single-display chooser, light appearance, keyboard crop movement, Refresh focus retention, and scrolling with a fixed footer at the minimum window size.
- After replacing the stale Settings entry once, a second build had a **different executable hash**, passed strict signature verification, and matched the first signed build's designated requirement. All four previews and a recording worked after relaunch without another permission prompt or Settings change. Local evidence is under ignored `test-results/screen-picker-rebuild-signing.json`.
- A real 9.4 s take saved as H.264/AAC at 2560 × 1440 and opened automatically in Editing Mode. `scripts/check-recording-timing.py` passed: audio/video start difference **10.7 ms**, end difference **44.0 ms**, with strictly increasing packet timestamps. Full decode passed using `ffmpeg -v error -i <take> -enc_time_base:v 1:1000000 -fps_mode passthrough -f null -`; an explicit encoder time base avoids rounding variable-rate timestamps to the null muxer's default frame grid. This checks track boundaries and decode, not perceptual lip sync.

Not exercised on hardware: macOS 14.x, mirrored displays, and physical disconnect/resolution changes during selection. Those transitions are covered at the controller/identity seams, but still need supported-OS and hardware QA. No CPU/memory benchmarks were performed, and no performance superiority over live thumbnail streams is claimed.
