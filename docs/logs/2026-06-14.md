### Native screen: region selection + multi-display (`native-screen-region-and-display.md`)

**Backend (`src-tauri`):**

- **`screen.rs`** — added `CaptureRegion { x, y, width, height: u32 }` (Clone, Debug, Deserialize) and `region: Option<CaptureRegion>` to `ScreenCaptureConfig`; added `DisplayInfo` (Serialize, camelCase) and `list_displays()` Tauri command that enumerates SCK displays on macOS (returns index, displayId, width, height, isPrimary where isPrimary = frame.x == 0 && frame.y == 0).
- **`screen_macos.rs`** — `new()` uses region dimensions (clamped to display bounds) when region is set; `start()` applies `with_source_rect` + `with_scales_to_fit(false)` when region is Some, and includes region in the start log: `Screen capture started: WxH @ Nfps region=Some(...)`.
- **`screen_stream.rs`** — added `region: Option<CaptureRegion>` param between `max_dimension` and `on_frame`; passes into `ScreenCaptureConfig`.
- **`manager.rs`** — patched legacy `ScreenCaptureConfig` init to include `region: None` (required after adding the field).
- **`lib.rs`** — registered `screen::list_displays` in the command handler.

**Frontend:**

- **`native-screen.ts`** — added `DisplayInfo` interface, `listDisplays()`, and `region?` to `NativeScreenOptions`; passes `region: opts.region ?? null` in the `start_screen_stream` invoke.
- **`preview.tsx`** — replaced immediate-start `startNativeScreen` with a picker→region flow: calls `listDisplays()`, shows a `Dialog` display picker if >1 display (otherwise skips straight to `RegionSelector`), then on region confirm starts the stream with `{ displayIndex, region }`. Added `handleDisplayConfirm` / `handleDisplayPickerClose` handlers. `handleRegionConfirm` now checks `nativeRegionPendingRef.current` first (native path) before the browser path. `stopNativeStreamForSection` now also clears `sectionRegions.current[index]` to prevent stale-crop reuse. `handleRegionCancel` clears `nativeRegionPendingRef`.
