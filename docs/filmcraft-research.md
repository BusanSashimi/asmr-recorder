# FilmCraft source research and migration inventory

Research date: 2026-10-16. Reference: [storytold/filmcraft](https://github.com/storytold/filmcraft), revision **`8309f21a6c3f34ddf190af7fd9bfd913053a1fd5`**, workspace version **0.8.0**. The local `reference/` checkout and remote HEAD matched this revision when inspected.

**Evidence status:** source inspection and primary-source web research, not runtime validation. The researcher read the reference's `AGENTS.md` and `CLAUDE.md`, inspected command implementations, model definitions, rendering, playback and platform code, and checked the Rust download endpoint. No complete FilmCraft build, codec conformance run, performance benchmark or end-to-end runtime verification was performed as part of this research. This document describes upstream capabilities and integration requirements; it does not certify that every capability has been exposed or tested in ASMR Recorder.

## Migration conclusion and mode ownership

Reuse FilmCraft's headless Rust engine and supporting crates; implement its user-facing workflows in ASMR Recorder's React design system. The engine is explicitly separated from egui and exposes `Session::execute(id, params)`. Reimplementing the algorithms would duplicate hundreds of commands, exact-time edit algebra, codecs, DSP, rendering, persistence and interchange. Reusing the core does **not** migrate the UI automatically: interactive timelines, monitor tools, inspectors, graphs, dialogs and real-time playback integration still require implementation. [Engine facade](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/lib.rs), [architecture](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/docs/architecture.md).

Recommended product assignment:

- **Recording Mode:** existing screen/window/region/camera/microphone/system-audio capture, capture setup and countdown, live input meters, start/pause/stop, capture destinations and take metadata.
- **Editing Mode:** media organization, source and program monitors, timeline editing, effects, color, titles, captions, mixing, proxies, export and interchange. Timeline voice-over belongs here because it records against sequence timing and produces an undoable timeline edit. Multicam playback switching also belongs here.
- **Shared:** project identity, settings, audio hardware choices, shortcuts, jobs, save and recovery status. Finalize a recording before transferring its media into the editing project. Preserve edits across mode changes.

This is an ASMR Recorder product recommendation, not an upstream requirement. Preserve upstream semantics without copying FilmCraft's Premiere-like appearance; new surfaces must follow the application's existing Apple-aligned components and tokens.

## Limitations and misleading breadth indicators

- **Optional speech features:** engine defaults are empty. Transcription requires `whisper`; downloads require `speech-download`; neural TTS requires `neural-voices`. Imported/manual transcript editing is separate from inference. [Engine features](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/Cargo.toml), [explicit unavailable errors](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/transcript.rs).
- **Unsupported Adobe compatibility:** `.mogrt` is explicitly rejected in favor of `.fcgt`; `.prproj` import is not implemented. Plugin preference categories are a stub; no VST/AU/OpenFX hosting. [Template rejection](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/graphic_templates.rs), [settings](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/settings.rs), [upstream gaps](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/docs/gaps.md).
- **Algorithm fidelity:** upstream describes Warp Stabilizer as 2-D and Morph Cut as optical flow without face tracking. Existence is not a fidelity guarantee. Effects requiring neighboring frames/tracks leave the image unchanged without `FxEnv`; the source explicitly identifies isolated tests/adjustment layers as such contexts. [VFX environment](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/render/src/vfx/mod.rs), [depth limitations](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/docs/gaps.md).
- **Capability gating:** HEVC export requires a registered hardware encoder. An AV1 export enum is not evidence of an available encoder; no AV1 native encoder implementation surfaced in inspected platform sources. Query runtime availability rather than exposing every enum as supported. [Formats](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/export/src/lib.rs), [platform registration](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/platform/src/lib.rs).
- **Stored-only options:** multicam Transmit View persists a setting; there is no external video-transmit device integration. [Architecture discussion](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/docs/architecture.md).
- **History limit:** despite README wording about unlimited undo, `Session` and new/open-project paths default to a limit of 200 snapshots. [Session](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/lib.rs), [project commands](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/commands.rs).
- **Documentation drift:** gaps mention absent AVI and multicam paging, whereas the pinned source contains an AVI crate and implemented multicam pages. Source inspection takes precedence over these stale entries. [AVI crate](https://github.com/storytold/filmcraft/tree/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/avi), [multicam](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/multicam.rs).

## Integration contracts

### Session, state and persistence

`Session::default()` installs native filesystem services; `Session::new(Arc<dyn Services>)` injects them. `execute(&mut self, id: &str, params: Value) -> Result<Value>` dispatches mutations and queries. The project is `Arc<Project>` with snapshot undo. `find_command(id)` exposes metadata and an enabled predicate; `command.list` returns IDs, labels, menu paths, shortcut fields, parameter documentation strings and enabled booleans. Those parameter strings are **not a machine-readable JSON Schema**. [Engine API](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/lib.rs), [registry](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/commands.rs).

`start_autosave(AutosaveConfig::new(data_dir))` loads preferences/presets, discovers recovery candidates and starts persistence. Call `poll_persistence()` periodically: it also applies proxy, mask and scene-analysis results and advances export queues. Call `shutdown()` on clean exit. Do not assume importing `Session` automatically enables recovery. [Lifecycle API](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/lib.rs), [configuration](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/autosave.rs).

Inspection traps:

- `sequence.inspect` provides convenient timeline fields, but effect parameter `value` is a Rust debug string. Serialize actual `EffectInstance`/`Param` or create a dedicated DTO for editable inspector values and keyframes.
- `state.inspect` serializes `EditorState` with snake_case fields; custom project/sequence inspection uses mixed custom camelCase fields.
- `ParamValue` serializes as tagged variants such as `{"Float":1}`, `{"Vec2":{"x":0,"y":0}}`, `{"Choice":0}`, `{"Color":[1,1,1,1]}`. `effects.setParam` instead accepts user-friendly raw numbers/arrays/bools/choice labels. Convert explicitly rather than sending stored tagged values unchanged.
- `file.import` can return success with both imported `items` and `errors`; show partial failures.

[Inspection serialization](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/commands.rs), [parameter representation](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/project/src/keyframe.rs).

### Time and command examples

`Tick(i64)` uses 254,016,000,000 ticks/second. JavaScript's integer precision ceiling is reached around 9.85 hours at that resolution. Transport ticks and large IDs losslessly, for example as decimal strings converted to native integers at the Rust boundary. Upstream `time_p` expects native integer JSON values, not decimal strings. Prefer frame arguments for frame-aligned UI gestures and exact ticks for source/audio/keyframe positions. [Time model](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/time/src/lib.rs), [time parsing](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/commands.rs).

### Frames and native playback

`Session::try_render_program_at(scale: f32, Tick) -> Result<Image>` renders the active sequence without moving its playhead; it snaps to a frame, clamps negative time and includes captions. `try_render_program_with_offline_at` also identifies offline media. `Image {w:usize,h:usize,px:Vec<f32>}` is premultiplied linear RGBA and is not serde-serializable. `over_black_rgba8()` returns opaque sRGB monitor bytes; `to_rgba8()` preserves alpha. Use bounded binary frame delivery with request/revision identity rather than full-resolution JSON arrays or base64 events. [Rendering API](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/lib.rs), [Image](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/render/src/image.rs).

Playback is not wholly in the headless engine: `FrameServer`, caching/prefetch/preroll, `AudioOut` and transport coordination live in `ui-egui`. Native cpal output lives in the desktop app. Extract their nonvisual mechanisms rather than bringing egui into the React interface. [Frame server](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/frames.rs), [playback/mixing](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/lib.rs).

Minimal robust audio extraction:

1. Adapt desktop `audio.rs`, replacing its `filmcraft_ui_egui::{AudioDevices,AudioOut}` import with local equivalents and replacing `Note::text` localization calls. Remaining code uses std, cpal, log and engine audio preferences; it includes device recovery, sample conversion and a played-frame clock.
2. Reuse `play_ahead.rs`: it is already egui-free, mixes on a background thread into a bounded atomic ring, reports underruns and stops when its callback is dropped. Never decode/mix video or perform file I/O in the device callback.
3. Extract `playback_mix` and the two voice-over cue helpers. It captures project/provider/previews and applies device-rate resampling, mapping, stereo/5.1 and live project updates.
4. Configure output before reading rate/channels. Build the mixer at the device rate, use `anchor.to_units_floor(rate)` for its start cursor, and start the mix-ahead callback.
5. Drive playhead from `anchor + Tick::from_units(played_frames, rate)` after `recover()`. Stop/restart on seeks, stop at sequence end and finalize active automation/voice-over/multicam passes on stop.

[cpal output](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/apps/filmcraft/src/audio.rs), [mix ahead](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/play_ahead.rs), [cue helpers](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/panels/voiceover.rs).

`shuttle.rs` is also largely UI-independent; its dependencies on enclosing playback helpers can be extracted. ## Additional integration inspection

### Source monitor

`filmcraft_engine::clip_ops::source_view(&session, item)` returns a `SourceView` containing the selected item, root media item, start/end, frame rate, marks and subclip range. Its `to_json(source_playhead)` method exposes monitor metadata. Source positions for subclips are absolute positions in the root media, so render `view.media` at the source playhead through `filmcraft_render::render_item(&project, view.media, time, scale, &provider)`. The provider comes from `session.media.provider(project.clone(), services.clone())`. The marked Out is inclusive; `selected_range()` adds one frame before forming the half-open range. [SourceView](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/clip_ops.rs), [render_item](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/render/src/lib.rs).

Source audio auditioning can reuse `source_playback.rs`'s nonvisual closure: obtain `provider.source(view.media)`, call `source.audio(cursor, frames, device_rate)`, apply interpreted audio-channel selection, `render::audio::to_layout` and `engine::settings::map_output`, then use the mix-ahead ring. Its upstream implementation plays sound at 1x only and supports media/subclips, while sequence-source audio auditioning is not implemented there. Starting source playback stops program playback. Decoder errors have a per-seek failure slot to prevent an old callback stopping a new seek. [Source playback](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/source_playback.rs).

### Captions and export availability

`captions.list {}` is a convenient UI query returning `{tracks,selection}`. Tracks expose `id,label,name,format,language,enabled,locked,syncLock,style,captions`; styles use CSS-like hex colors and lowercase alignment/anchor names. Captions expose `id,start,end,in,out,duration,text,speaker,settings`. **The query's `duration` is a formatted timecode string**, whereas `start/end` are ticks. Raw model serde instead uses snake_case fields and enum values such as `Cea608`, `Center` and `Bottom`. [Caption query](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/captions.rs), [raw model](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/project/src/caption.rs).

Useful editing commands include `captions.add {track?,text,frame?,durationSeconds}`, which creates a track when absent; `captions.setText {caption,text,speaker?}`; `captions.setTimes {caption,startFrame,endFrame}`; `captions.trim {caption,edge,deltaFrames}`; `captions.move {captions,deltaFrames}`; `captions.delete {captions,ripple}`; and `captions.setStyle {track,font,size,color,background,backgroundColor,align,anchor,margin,lineSpacing,outline,outlineColor}`. `captions.export` accepts SRT, VTT, SCC, MCC, STL, TTML and DFXP. [Command definitions](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/captions.rs).

`export.formats {}` returns `[{id,label,extension,video,audio,imageSequence,available}]`. Run it after native platform registration; filter or explain unavailable entries. Additional Rust `filmcraft_export::hdr_available(format)` indicates whether a registered encoder advertises HDR output. Basic format availability alone does not guarantee HDR. [Format query](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/export_tools.rs), [availability probes](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/export/src/lib.rs).

### Shortcut routing

`shortcuts.resolve {keys:"Cmd+K",panel:"Timeline",platform:"mac"}` returns `{command,panel}` or null. Shortcut list/get/set/clear/conflicts/preset/import/export operations are implemented. `session.shortcuts.register_external(Vec<CommandInfo>)` adds frontend routes; only register routes actually implemented by ASMR Recorder. UI-only commands must not be sent to `Session::execute`. Examples are `playback.toggle` (Space), `playback.forward` (L), `playback.stop` (K), `playback.reverse` (J), `source.playback.*`, `view.zoomIn/zoomOut/zoomToSequence`, `mode.export` (Cmd+M), `voiceover.recordToggle`, `tool.selection` (V), `tool.razor` (C), `tool.ripple` (B) and `tool.rolling` (N). Window/layout/language/branding/preferences commands require local frontend equivalents, not automatic import. Commands requiring paths/settings need dialogs before dispatch. Resolve source-focused commands against Source context rather than editing the program playhead globally. [Shortcut engine](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/shortcuts.rs), [UI command table and routing](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/menus.rs).

### Native voice-over and frame-worker lifecycle

Desktop `audio_in.rs` is already egui-free. `CpalIn::new(host)` implements the engine's `AudioInput` and can be installed as `session.voiceover.input = Some(Box::new(input))`. Its own thread owns the native stream, handling backends whose streams are not Send. It accumulates the take until stopped, with a ceiling of 268,435,456 interleaved samples and explicit overflow errors; it is not an unbounded disk-streaming recorder. [Input adapter](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/apps/filmcraft/src/audio_in.rs).

`audio.voiceover.start {track,time?,preroll?}` returns `captureStart,recordStart,punchOut,postroll,cues,sampleRate`. The host seeks to captureStart and starts playback, then calls `audio.voiceover.sync` when the audio clock actually begins. Stop at current timeline time through `audio.voiceover.stop {time,dir?,discard?}`. Settings expose device/channel, cue sounds and pre/postroll. This requires real microphone permission and coordination with recording-mode device ownership. [Engine voice-over](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/voiceover.rs), [transport orchestration](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/panels/voiceover.rs).

`frames.rs` has one direct egui coupling in `set_context`: its repaint storage is already a `Box<dyn Fn() + Send + Sync>`, which can become a host callback setter. Dependencies include engine/project/time/render/gpu/frame/media/geom, web-time, serde_json/log, rustix time on Unix and cpu-time on Windows. Its crash-injection hook references the UI crash module. **The upstream worker loop has no shutdown signal or Drop implementation**, retains strong Arcs and ignores thread-spawn errors. Do not recreate servers on every project or mode switch without lifecycle fixes. `file.open` replaces `session.media`; a server capturing the previous MediaPool must be updated/replaced, with old workers stopped and joined. Its caching, revision/request identity, priority scheduling and cancellation are valuable, but require ownership integration rather than a blind copy. [Frame server](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/ui-egui/src/frames.rs), [project installation](https://github.com/storytold/filmcraft/blob/8309f21a6c3f34ddf190af7fd9bfd913053a1fd5/crates/engine/src/commands.rs).
